# Phase 6 Grill-Me Protocol

Interview me one question at a time until the semantic compilation architecture is sufficiently specified for implementation.

For every question:
- inspect the Phase 6 source-of-truth documents first;
- explore the codebase or existing registry before asking when evidence exists there;
- provide a recommended answer before asking me to decide;
- identify the architectural collision motivating the question;
- explain the implementation consequence.

## Mandatory investigation order

1. Current Primitive Registry topology
2. SDA registry topology
3. Existing coalition / receipt implementation
4. Candidate-generation mechanics
5. Primitive geometry and scoring
6. Compatibility / antagonism representation
7. Edge Product taxonomy
8. SQL / JSONB / vector query functions
9. Validator and error contracts
10. Brownfield migration

## Recommendation law

Recommendations must obey RSCS:
- saturation before compression;
- meaning through collision;
- compression increases signal density;
- evaluation governs reality contact.

## No generic recommendations

A recommendation must be grounded in:
- existing CAE objects,
- Phase 5 evidence model,
- existing primitive registries,
- existing Matrix of Edging,
- SDA artifacts,
- existing codebase behavior.

## Anti-centroid requirement

Do not recommend simplification merely because it is easier.

If a structural distinction carries meaningful execution value, preserve it and explain why.

## Question sequencing

Resolve foundational dependency decisions first:
- object identity and role;
- candidate semantics;
- scoring basis;
- coalition legality;
- Edge Product identity;
- query surface;
- validation;
- migration.

Do not ask downstream rendering questions before semantic force objects are stable.
