# Grill-Me Protocol — Phase 4: Pressure, Edging & Activation

Interview me relentlessly about Phase 4 until shared understanding is reached.

## Laws
1. Ask one question at a time.
2. If the codebase or supplied source can answer it, inspect the source instead of asking.
3. Every recommended answer must be substantive and project-specific.
4. The recommendation must preserve the Anti-Centroid Doctrine and the Human-First Boundary.
5. Distinguish evidence, inference, hypothesis, and policy.
6. Do not introduce generic safety/censorship language that is not part of CAE doctrine.
7. Surface collisions rather than averaging them away.
8. Explain which Phase 2/3 objects the recommendation depends on.
9. State what the decision authorizes and what it does not authorize downstream.
10. Treat Matrix of Edging as a tension-selection system, not a copywriting style guide.

## Required question branches

### A. Tension ontology
- What makes a Tension materially different from a Signal?
- What distinguishes Tension from Pressure?
- When should a Tension become a Webhook?

### B. Evidence and state
- What is the minimum evidence density for an active tension?
- How many independent signals are required before state promotion?
- How should contradictory evidence affect state?

### C. Matrix of Edging
- Which dimensions are canonical?
- Which dimensions are configurable?
- What makes a candidate survive?
- How are alternatives preserved?

### D. Anti-centroid
- What exactly counts as RLHF-style flattening?
- When is softening legitimate and when is it corruption?
- Which terms/patterns should trigger patrol without suppressing sharpness?

### E. Human-first activation
- How broad must the Primary Signal remain?
- What presuppositions are forbidden?
- What makes an ActivationEvent specific without scripting the answer?

### F. Webhooks
- Which webhook classes exist?
- What state transitions fire them?
- What cooldown and saturation logic is required?

### G. Brownfield integration
- Which current implementations are authoritative?
- Which are duplicated?
- Which schemas need adapters rather than replacement?
- Which Phase 4 decisions require an explicit migration flag?

## Recommendation format
Every recommended answer SHALL follow the current CAE Grill-Me / RSCS discipline: saturated project context → collision detection → compressed recommendation → explicit evaluation gate.
