# Phase 4 Build Order

## Stage 1 — Brownfield audit
Inventory the existing Matrix of Edging, webhook/activation terminology, Trigger-First Engine, Context Premise extraction, psychological routing, anti-draft, anti-centroid, and any existing trigger/edge schemas or code.

## Stage 2 — Tension ontology
Separate Topic, Signal, Tension, Pressure, Webhook, Edge, and Broad Primary Signal. Define their boundaries before coding.

## Stage 3 — Tension state model
Implement latent / emerging / active / saturated / cooling / resolved / superseded / corrupted states with temporal provenance and evidence thresholds.

## Stage 4 — Pressure field model
Create a derived, provenance-preserving field that combines relational assessments, audience state, guest state, invariants, cultural signals, freshness, and contradictions.

## Stage 5 — Matrix of Edging doctrine
Convert the existing Matrix into explicit selection dimensions, candidate generation, survival, ranking, routeability, and anti-centroid patrol rules.

## Stage 6 — Webhook / activation selection
Define when a tension becomes eligible to trigger an activation event, and what must remain broad so the Guest is not led into a prewritten conclusion.

## Stage 7 — Broad primary signal compiler
Generate a small candidate set, score it, retain alternatives, and emit an auditable BroadPrimarySignal object.

## Stage 8 — Activation event compiler
Translate the selected broad signal into a human-first activation event using the appropriate questioning grammar without manufacturing the Guest's answer.

## Stage 9 — Anti-centroid patrol
Run a dedicated patrol against averaging, sanitization, genericization, over-safety injection, and pressure dilution.

## Stage 10 — Event and receipt wiring
Persist candidate lineage, rejected alternatives, patrol results, and the activation outcome expected from Phase 5.

## Stage 11 — Technical convergence
Produce PostgreSQL/JSONB models, Pydantic models, authorized SQL functions/views, planner programs, validators, and event schemas.

## Exit gate
A selected activation event must be reproducible from stored evidence and selection receipts without relying on hidden conversational memory.
