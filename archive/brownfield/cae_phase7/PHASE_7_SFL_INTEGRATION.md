## Runtime stack rules

A stack MUST:
- reference canonical function IDs
- have primary/secondary functions
- have bounded weights
- declare target surface
- declare intended effects
- declare alignment constraints
- preserve edge/invariant lineage

A stack MUST NOT:
- invent new canonical functions at runtime
- use a function to silently rewrite invariant direction
- substitute “safe” genericity for failed selection
- treat perceptual potency as a reason to override semantic truth

## Canonical + poetic requirement

SFL definitions may contain a controlled poetic invocation layer for human interpretability, provided that the executable fields remain explicit. The poetic layer is not the schema and cannot override typed parameters.

This gives:

```text
Canonical mechanics
+
Poetic invocation
+
Typed runtime contract
```

rather than prose-only magic.
