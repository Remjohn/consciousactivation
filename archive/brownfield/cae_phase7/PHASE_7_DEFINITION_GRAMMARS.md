# Phase 7 Definition Grammars

## Global rule

**Role-before-schema:** identify the architectural role and artifact class first. Only then derive the schema.

Definitions must establish:
1. Genus
2. Differentia
3. System Function
4. Semantic Boundary
5. Distinction from nearest neighbors

Definitions must not introduce moralizing, unnecessary permission language, RLHF-style hedging, or unsupported safety constraints.

## ArchetypeContainerDefinition grammar

**Target length:** 150–300 words.

**Required semantic sequence:**
- what kind of structural object it is
- what semantic job it performs
- what invariant topology it preserves
- what phases/slots it governs
- what it may vary
- what it cannot become without ceasing to be this archetype
- distinction from format, scene, style, and Edge Product

## SFLFunctionFamilyDefinition grammar

**Target length:** 80–160 words.

State:
- perceptual domain
- family-level mechanism
- role in delivery
- relation to SFL functions
- boundary against semantic ontology and primitive operators

## SFLFunctionDefinition grammar

**Target length:** 150–300 words.

Must answer:
- what perceptual modulation it performs
- what signal it acts on
- when it is useful
- what parameters control intensity or application
- expected perceptual effect
- anti-patterns / failure signatures
- relation to semantic force
- boundary against neighboring functions

## SFLInfluenceAlignmentPolicy grammar

**Target length:** 150–350 words.

Must specify:
- scope
- allowed influence behavior
- disallowed misalignment
- brand/coach constraints
- semantic integrity dependency
- escalation condition

The policy must distinguish ethical/legal constraints from merely stylistic discomfort. It must not encode generic “be safe” softening.

## CompositionDepthProfile grammar

**Target length:** 100–220 words.

Must specify:
- the depth mechanism
- what it changes in perception / structure
- admissible parameter ranges
- where it may be applied
- how it differs from SFL and archetype structure

## JITDirective grammar

**Target length:** 70–180 words.

Must specify:
- issuer
- directive type
- target object/layer
- intended effect
- priority
- prohibited interpretation
- source lineage
- override behavior

## SemanticProgram grammar

**Target length:** 100–220 words.

Must specify:
- what it represents
- the authorized semantic execution plan
- upstream lineage
- downstream contract boundary
- non-authorized concerns
- version and validity window

## Receipt grammar

A receipt is not explanatory prose. It is an immutable execution trace that records:
- inputs
- decisions
- selected/rejected alternatives
- policy/version snapshots
- validator verdicts
- resulting object
- timing and actor IDs
