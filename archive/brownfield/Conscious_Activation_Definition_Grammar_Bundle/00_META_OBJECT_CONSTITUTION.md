# META OBJECT CONSTITUTION

## Purpose

Defines the universal meta-grammar used to classify any Conscious Activation artifact before applying an object-class-specific definition protocol.

## Required identity block

Every object definition begins with:

- `canonical_id`
- `object_name`
- `artifact_class`
- `ontological_plane`
- `architectural_role`
- `lifecycle_class`
- `authority_class`
- `execution_role`

## Semantic identity

The author MUST distinguish:

- canonical name
- approved aliases
- prohibited aliases
- identity statement
- nearest semantic neighbors

## Artifact class

The artifact class determines the object-specific grammar. It is not selected because a schema is convenient.

## Ontological plane

The plane identifies the domain in which the object primarily operates. Suggested planes include:

- `TRUTH_CONTEXT`
- `SEMANTIC_DISCERNMENT`
- `MEANING_FORCE`
- `EXPERIENCE`
- `PERCEPTUAL_DELIVERY`
- `REALIZATION`
- `EXECUTION`
- `EVALUATION_MEMORY`

An object may participate in multiple planes through crosswalks, but it should have one declared primary plane.

## Lifecycle class

Choose exactly one primary lifecycle classification:

- `CANONICAL`
- `DYNAMIC`
- `IMMUTABLE_EVIDENCE`
- `DERIVED`

## Required universal questions

Every protocol must establish:

1. What is it?
2. Why does it exist?
3. What is it not?
4. What are its nearest neighbors?
5. What can change?
6. What must remain invariant?
7. Who owns it?
8. What may operate on it?
9. What validates it?
10. What evidence supports the definition?

## Completion criterion

A definition is complete when a qualified architect or agent can classify the artifact, distinguish it from its nearest neighbors, understand its function, and determine its authority and lifecycle without requiring an unwritten explanation.
