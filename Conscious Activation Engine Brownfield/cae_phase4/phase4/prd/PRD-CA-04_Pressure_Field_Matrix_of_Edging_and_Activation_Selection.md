# 1. Purpose

Phase 4 defines the **Pressure Selection and Activation Layer** of the Conscious Activation Engine (CAE).

Its purpose is to transform relational intelligence into a controlled, evidence-grounded selection of the pressure most worth activating in a human-first workflow.

The core question is:

> **Which unresolved human pressure has enough current relevance, relational support, evidence density, collision intensity, and downstream potential to justify an activation attempt?**

The output is not the Guest's answer. It is a broad, carefully bounded signal and an activation event designed to elicit the Guest's own answer.

# 2. Architectural position

```text
WORLD INTELLIGENCE
      ↓

      ↓

      ↓
MATRIX OF EDGING
      ↓

      ↓
ACTIVATION EVENT

      ↓
```

## 2.1 Constitutional boundary

Phase 4 may select, sharpen, rank, and frame pressure.

Phase 4 MUST NOT:

- fabricate a Guest conclusion;
- transform a hypothesis into authenticated evidence;
- erase contradictory evidence to create harmony;
- substitute generic engagement heuristics for the project's relational data;
- use safety-sounding language to dilute a legitimate high-charge signal;
- decide final content form, scene, visual syntax, or edit rhythm.

# 3. Ontological correction

The system previously used several neighboring words loosely. Phase 4 canonicalizes them.

| Object | Canonical question |
|---|---|
| Topic | What broad subject domain is being discussed? |
| Signal | What observable event/data point is currently relevant? |
| Tension | What unresolved meaningful boundary is producing pressure? |
| Pressure | How much force is this tension currently carrying in context? |
| Webhook | What stateful activation condition can trigger an upstream response attempt? |
| Broad Primary Signal | What broad pressure cue is ready to place in front of the Guest? |
| Activation Event | What question/prompt will invoke the Guest without pre-writing the answer? |
| Edge Product | What sharpened tension object emerges after authenticated evidence and coalition formation? |

The distinction between BroadPrimarySignal and EdgeProduct is mandatory. The former precedes authenticated Guest evidence; the latter follows it.

# 4. Pressure Field

The Pressure Field is a derived representation of currently meaningful unresolved pressures. It is generated from:

- Audience current state
- Audience evidence and Context Premise
- Guest current state and historical experience
- Guest–Audience congruence
- Existential invariant activation
- cultural and research signals
- temporal freshness
- contradiction and asymmetry
- audience maturity/capacity
- prior activation history
- prior performance history

Every PressureFieldCandidate MUST preserve lineage to its contributing evidence.

# 5. Tension ontology

A Tension is a meaningful unresolved pressure at a human boundary where two or more conditions, expectations, values, identities, desires, behaviors, or realities cannot be treated as fully equivalent without losing signal.

Tensions may be:

- identity
- belief
- value
- relational
- status
- practical
- aspirational
- cultural
- temporal
- mechanism-based
- existential

Tension types are taxonomy, not rhetorical labels. A tension may have multiple typed dimensions but MUST retain a primary classification for routing.

# 6. Tension states

The canonical state machine is:

```text
latent → emerging → active → saturated
                 ↓         ↓
               cooling   resolved
                 ↓         ↓
             superseded / archived
```

A separate `corrupted` state is used when the evidence supporting a prior interpretation is contradicted, contaminated, or found to be invalid.

States are observations over time; they do not rewrite historical evidence.

# 7. Webhook doctrine

A Webhook is a stateful activation condition indicating that a canonical tension or pressure field has crossed the evidence, relevance, and timing conditions necessary to trigger a defined system response.

A Webhook is therefore **not** a hook line.

A Webhook contains:

- target object(s)
- trigger condition
- evidence threshold
- freshness window
- state requirement
- cooldown / saturation rule
- downstream action
- confidence
- provenance

A Webhook may trigger an activation attempt, research update, state refresh, or review. It does not itself contain the final creative wording unless an ActivationEvent has been compiled from it.

# 8. Matrix of Edging

The Matrix of Edging is the controlled selection doctrine for meaningful human pressure.

It has two primary phases.

### Phase A — Broad Primary Signal

Purpose: provoke authentic Guest reaction without over-determining the response.

The broad signal should be:

- current
- relevant
- evidence-backed
- broad enough for surprise
- specific enough to carry pressure
- semantically native to the audience/guest relationship
- protected from centroid dilution

### Phase B — Edge Product

Purpose: sharpen authenticated human material into an executable tension object.

The edge product is selected only after human evidence exists and the primitive/coalition layers have legitimate source material.

# 9. Candidate generation

The Matrix MUST generate a bounded candidate field rather than commit to the first plausible pressure.

Candidate dimensions SHOULD include:

- evidence density
- current-state relevance
- invariant activation
- congruence support
- collision intensity
- freshness
- audience recognition potential
- novelty
- speakability
- downstream routeability
- historical survival

# 10. Candidate survival

Candidate survival is a typed selection stage.

A candidate is eligible only when required evidence thresholds pass.

The survival record MUST preserve:

- candidate score vector
- strongest supporting evidence
- contradictory evidence
- nearest competing candidates
- failure reasons
- decision state

The goal is not to maximize one scalar blindly. The goal is to retain the candidate with the strongest high-signal geometry under constraints.

# 11. Anti-centroid doctrine

Anti-centroid protection is a first-class quality system.

It specifically patrols for:

- polite averaging
- false balance
- generic compatibility language
- over-safety substitutions
- hedge inflation
- de-charge through abstraction
- removal of uncomfortable asymmetry
- replacing a live edge with a consensus statement
- importing moralizing or authorization language not present in the task

The patrol MUST distinguish legitimate narrowing from centroid flattening.

A candidate may be rejected because it is unsupported. It may not be rejected merely because it is sharp.

# 12. Activation Event

An ActivationEvent is the executable human-facing prompt generated from a BroadPrimarySignal.

It must preserve three things:

1. the pressure being explored;
2. the freedom of the Guest to answer from their own experience;
3. sufficient specificity to trigger authentic thought rather than generic commentary.

The ActivationEvent MUST NOT preload the Guest's conclusion.

A strong ActivationEvent is therefore:

```text
broad pressure
+ precise context
+ semantic specificity
+ invitation to explain
- prewritten answer
```

# 13. Human-first gate

Phase 4 ends at the interview boundary.

The constitutional sequence is:

```text
world model
→ relational hypothesis
→ broad primary signal
→ activation event
→ human response
→ authenticated evidence
```

No downstream system may treat the pre-interview hypothesis as authenticated Guest truth.

# 14. State and cooldown

Tensions and Webhooks are not allowed to fire indefinitely.

The runtime must support:

- activation counts
- cooldown windows
- saturation detection
- resolution detection
- diminishing-return monitoring
- reactivation conditions

A highly successful activation may become saturated. Saturation does not mean falsehood; it means that repeating the same trigger without new evidence is no longer expected to increase signal.

# 15. Provenance and evidence

Every candidate pressure must carry:

- evidence references
- evidence type
- observation timestamp
- source timestamp where different
- confidence
- derivation method
- relation lineage
- state lineage

Evidence classes SHOULD include:

- first-party human evidence
- first-party project memory
- direct research
- cultural signal
- derived inference
- hypothesis

Research provenance and epistemic status must be preserved separately.

# 16. Planning and SQL-of-Thought alignment

The Matrix of Edging should not be invoked through free-form reasoning over the whole database.

The preferred execution pattern is:

```text
Intent
→ Schema Link
→ Relevant Tensions
→ Relevant States
→ Relevant Guest/Audience Relations
→ Candidate Subproblems
→ Selection Plan
→ Candidate Generation
→ Candidate Survival
→ Validation
→ Typed Decision
→ Repair / Escalation
```

Authorized SQL views/functions should expose only the fields required for each step.

# 17. Error taxonomy

# 19. Acceptance criteria

A Phase 4 implementation is acceptable only when:

- pressure can be distinguished from topic and signal;
- webhook conditions are stateful and traceable;
- candidates preserve contradiction rather than average it away;
- broad signals remain pre-authentication hypotheses;
- activation events do not script Guest answers;
- every selection has a reproducible decision lineage;
- anti-centroid patrol is executable;
- SQL/JSONB retrieval can reproduce the candidate field;
- failed selections produce typed errors and targeted repair paths.
