# FR-CA-02-007 — Guest Dynamic State Model

## Requirement
GuestState MUST represent the time-bounded condition of a Guest relevant to current activation, interview, or content work.

## Constraints
State may include current concerns, convictions, active tensions, narrative focus, affective register, and transformation position.

## Implementation Principle
GuestState MUST NOT overwrite Guest identity or canonical VoiceDNA definitions.

## Acceptance Criteria
- Canonical identity/ownership is explicit.
- Object Constitution fields are defined or marked pending.
- Provenance and lifecycle are testable.
- No silent flattening of evidence into unsupported canonical claims.
- Brownfield status is recorded before replacement.
