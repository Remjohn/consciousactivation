## 1.2 Product Doctrine — What This Product Is

*Verified against code: 2026-08-01. Source: `governance/program-control/00_CONSTITUTION/current-v1.1/docs/03_PRODUCT_SYSTEM_TOPOLOGY_AND_PRD_ALIGNMENT.md`, v1.1.0, dated 2026-07-14. This is doctrine, not implementation status, so it does not decay the way the rest of this document does — but it is the frame every status claim below has to be read inside.*

Conscious Activations is not a content generator and not a single universal harness. It is a constitutional system that discovers human and audience pressure, compiles that pressure into structured intelligence, captures or activates authentic human expression, and routes that expression into separately-governed production systems. The doctrinal core: **content activates when it gives the viewer a psychological role inside a tension.**

The canonical chain:

```
Research and evidence
→ Coach/Guest Identity DNA
→ Audience Context Premise
→ Coach/Guest–Audience Resonance
→ Matrix of Edging
→ Activation Compiler
→ Activative Intelligence Pack
```

The pack then branches:

```
Conversational branch                          Visual branch
Activative Call                                 Visual Semantic Pack
→ human reply / interview answer                → Semiotic MCDA
→ Reaction Receipt                              → Visual Narrative Program
→ Expression Moment                             → format harness
→ post-expression recompilation                 → feature contracts
→ final Content Type Contracts                  → Composition Asset Pack
                                                 → Visual Syntax + exact composition
                                                 → visual production and evaluation
```

Both branches converge on shared evaluation and repair before shipping. Practically: the operator (a solo coach-facing content producer) turns one real human interview — either engineered live against a brief, or an existing upload — into short-form video, Carousels, SuperVisuals, and animation scenes for a coach client, with every step in the chain traceable back to the doctrine above rather than to a generic prompt.

The constitutional layer governs **three of the nine live subsystems**. Each owns a non-overlapping responsibility:

| Subsystem | Constitutional responsibility |
|---|---|
| **Builder** (`services/builder`) | Harness-development compilation: turns evidence and ratified product decisions into canonical Harness IR, graphs, skills, workflow specs, tests, Development Capsules, and implementation authorization. Must support both visual and Conversational Activation categories. |
| **Delegation** (`services/delegation`) | Preservation of immutable, versioned contract meaning and authority between Content Harnesses and the Visual Asset Editor. May not invent, compress away, or reinterpret semantic fields. |
