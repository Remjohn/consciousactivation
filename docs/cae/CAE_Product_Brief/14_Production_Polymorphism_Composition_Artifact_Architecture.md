# 14. Production Polymorphism, Composition & Artifact Architecture

CAE must support more than one production pattern without becoming a pile of conditional exceptions. This is the role of **production polymorphism**. Different campaign modes, artifact formats, evidence states, and delivery requirements may legitimately change how the engine operates, but those differences must be represented as explicit contracts rather than scattered `if/else` logic. Polymorphism is valuable only when it preserves the same constitutional spine.

The Product Brief therefore treats a production artifact as a typed object within a governed pipeline, not as a file created at the end. Every artifact should declare what it is, why it exists, what evidence supports it, what composition lane governs it, what assets it consumes, what model or transformation created its non-human components, and what authority state permits it to advance. This allows CAE to support multiple formats without making provenance and governance format-specific exceptions.

Production polymorphism starts with campaign modes. A **Retainer** represents recurring, planned production where a known cadence, package, and evidence-generation cycle exist. The engine can therefore optimize for repeatability, stable subject knowledge, recurring audience themes, and predictable delivery windows. An **Opportunist** mode responds to a timely event, collision, trend, or newly available evidence. It can prioritize speed and relevance while still requiring evidence, authority, and composition constraints. The two modes differ operationally, but neither becomes a back door around the constitutional system.

Artifact polymorphism then determines how the same semantic evidence can become different public objects. A short-form video can use VERBATIM_ONLY dialogue. A carousel or supervisual may use a VOICE_DNA_BRIDGED lane with a strict synthetic contribution cap. A headline or hook belongs to an EDITORIAL_HEADLINE lane and should not be displayed as if it were a direct Subject quotation. The format does not merely change the rendering template; it changes the legal and semantic contract of what language may appear where.

This is why **format must be declared before the interview**. If the system knows it needs a 60-second video, a four-card carousel, or a supervisual, it can define the evidence requirements, story shape, and elicitation segments necessary to produce that artifact. Post-hoc format squeezing is structurally prohibited because it forces evidence into a shape it was never collected to support. Production polymorphism therefore begins upstream with requirements, not downstream with templates.

The canonical artifact architecture should distinguish at least the following layers: **source evidence**, **evidence segment**, **semantic annotation**, **content candidate**, **narrative or storyboard object**, **composition**, **rendered artifact**, **semantic QA**, **render QA**, and **operator approval**. The runtime's lossless artifact lineage graph already reflects this general shape. The important principle is that each layer adds structure without erasing the relationships of the layer beneath it.

An artifact should be able to answer five questions without reverse engineering the entire database. What source evidence is this based on? What transformation happened? What synthetic material was introduced? What validation has passed? Who or what authorized the next state? The answer should remain available even after the artifact has been rendered into a final media file. Hashes, provenance identifiers, composition-lane metadata, and release records make that possible.

Composition is therefore an explicit stage. The Composer does not simply “write copy.” It assembles eligible evidence according to the artifact's contract. The composition object should contain the ordered evidence units, transitions, visual or audio asset roles, permitted synthetic bridges, and any editorial framing. It should also preserve the difference between source language and generated language. This makes the output inspectable before expensive rendering begins.

Asset polymorphism works the same way. The Asset Intelligence layer can distinguish real-world footage, previous interview footage, archival material, movie or cultural references, social media sources, stills, audio bites, video clips, and motion graphics. Each candidate can also carry an editorial insert role such as semantic simile, contrast, pattern interrupt, comedic punctuation, foreshadowing, cultural recognition, emotional amplification, or world building. These roles allow the composition system to request a type of media function rather than hard-code a single vendor or source.

Yet discovery is not approval. The asset object needs lifecycle, rights, provenance, timestamp, source hash, and semantic role. An unresolved candidate can be useful to the Hunter or Analyst but should not enter a release-ready composition. This is another example of polymorphism with a shared contract: the object can exist in multiple states, but each state permits only specific actions.

The same pattern applies to evidence candidates. A candidate can be discovered, analyzed, ranked, rejected, repaired, promoted, superseded, or archived. The state transition is explicit. This allows CAE to preserve failed alternatives and rejected candidates rather than silently overwriting them. That history becomes important for evaluation, learning, and audit because the system can later distinguish “the model never saw this candidate” from “the model saw it and the Operator rejected it.”

Production execution must also be polymorphic without creating multiple runtimes. The primary App, Operator console, and future chat adapters can all present different interaction patterns, but they should invoke the same canonical runtime. A rich web surface may allow asset inspection and storyboard editing. A message channel may surface a ready-for-review notification and accept a simple decision. The transport changes; the production object does not. This is a crucial safeguard against fragmented state.

Polymorphism should also govern model and tool choices. A deterministic extraction task may run without a frontier model. A multimodal asset evaluation may require visual reasoning. A complex narrative reconstruction may need a stronger model. The artifact contract stays constant while the intelligence implementation changes according to routing policy. This makes the system extensible without making the product semantically unstable.

The deepest principle is that **polymorphism changes realization, not authority**. A Retainer and an Opportunist campaign can differ in timing. A video and carousel can differ in composition lane. A local model and frontier model can differ in intelligence cost. A web UI and chat adapter can differ in interaction. None of those variations may bypass evidence provenance, human authority, release validation, or fail-closed behavior.

The resulting production equation is:

**Declared production requirement → polymorphic plan → eligible evidence → format-specific composition contract → validation → render → authority transition → release artifact.**

This architecture gives CAE flexibility without drift. It supports the real-world variety of activation production while keeping the system recognizable as one engine. Every variant still participates in the same causal graph, every artifact remains traceable, and every new format or campaign mode can be evaluated as a contract extension rather than as a special-case implementation.
