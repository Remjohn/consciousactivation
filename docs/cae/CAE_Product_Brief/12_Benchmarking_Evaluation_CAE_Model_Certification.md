# 12. Benchmarking, Evaluation & CAE Model Certification

CAE cannot treat model selection as a leaderboard exercise. The product does not need an abstract winner; it needs certified intelligence for specific transformations inside a governed production system. A model can be excellent at general reasoning and still be unsafe for exact evidence extraction, poor at preserving provenance, expensive for routine classification, or unreliable when asked to respect a strict output schema. Certification therefore belongs at the product boundary between model capability and CAE responsibility.

The first principle is **capability contract over model brand**. CAE may maintain a working stack and known-good control models, but no provider or model name is constitutional. The intended stack discussed in the product work includes Qwen3.8 27B xhigh, Qwen3.8-Flash-Next, GLM-5.3-Flash, Muse Glimmer, and Gemma 4 31B Reasoning, with Gemini 3 Pro retained as a historical or control reference where useful. The point of recording this stack is reproducibility and comparison, not vendor lock-in. The Product Brief should remain stable when a model is replaced by a better or cheaper certified implementation.

Certification begins with a **CAE task taxonomy**. The relevant tasks include Interview Brief construction, interview-question generation, transcript and evidence extraction, quote selection, collision and relationship analysis, narrative reconstruction, editing, visual or media planning, governance validation, and other production transformations. Each task has a different intelligence profile. Interview Brief work requires knowledge, retrieval, synthesis, and uncertainty handling. Transcript extraction requires long-context reasoning plus unusually high evidence fidelity. Quote selection is a constrained ranking problem. Narrative reconstruction requires synthesis without semantic corruption. Governance requires instruction fidelity, refusal behavior, and dependable boundary compliance.

Public benchmarks are useful but deliberately secondary. Artificial Analysis-style evaluations such as AA-LCR can act as screening signals for long-context reasoning; hallucination-oriented knowledge measures can help assess research and uncertainty behavior; agentic professional-work evaluations can provide evidence about broader orchestration; and large knowledge-work evaluations can approximate a model's ability to work across a substantial evidence base. These benchmarks answer important questions, but they do not answer the only question CAE ultimately cares about: **can this model perform the exact CAE transformation while preserving evidence, provenance, authority, and output integrity?** Public benchmarks are therefore screening signals, not product truth.

CAE needs its own benchmark family: the **CAE Semantic Extraction Benchmark (CSEB)**. CSEB should evaluate the production-critical transformation from recorded human evidence to canonical semantic objects and eventually to governed artifact candidates. Test cases should contain source transcripts, known evidence spans, relationships, contradictions, context, target artifact requirements, and gold-standard human decisions. Evaluation dimensions should include quote exactness, evidence fidelity, relevant coverage, ranking quality, relationship reconstruction, narrative coherence, unsupported inference, provenance preservation, schema compliance, and appropriate refusal when evidence is insufficient.

CSEB should not become a single headline number. A model with high extraction accuracy but poor provenance is not equivalent to a model with slightly lower extraction accuracy but almost no unsupported inference. CAE should therefore maintain a **multidimensional certification profile**. Candidate models can be certified per task, per composition lane, and per operational risk class. “CAE-certified” should mean that a model has passed the gates relevant to the work it is authorized to perform, not that it has acquired a universal badge.

The certification gate should include at least five dimensions. **Semantic reliability** asks whether the model preserves source meaning and identifies the right evidence. **Governance reliability** asks whether it follows output contracts, respects authority and refuses prohibited actions. **Operational reliability** measures timeout, retry, fallback, latency, and schema-failure behavior. **Economic reliability** examines cost per accepted transformation rather than raw token price. **Human agreement** measures how often the model's recommendations survive Operator review without substantive correction.

The control corpus should contain real CAE examples wherever rights and consent permit. Historically successful interview-to-artifact transformations are especially valuable because they establish a known-good reference. But the control corpus must not become a hidden oracle that encodes one Operator's preferences forever. It should contain variation in topics, Subjects, audience contexts, artifact types, and failure cases. Negative examples matter just as much: unsupported claims, genericized paraphrases, wrong-speaker attribution, context-stripped quotes, weak evidence candidates, and invalid composition should all be represented.

Evaluation must also be versioned. A certification result should identify the model version, task suite version, data revision, evaluator version, routing conditions, and policy configuration. This makes model changes comparable and protects against benchmark drift. When a model is upgraded, CAE should not assume backward compatibility because a vendor kept the same public name. Re-certification is the default for capability changes that can affect semantic or governance behavior.

Certification should distinguish **hard gates** from **optimization metrics**. A model can be allowed to lose a small amount of speed while maintaining an absolute provenance requirement, but it should never be allowed to trade evidence sovereignty for speed. Some failures should therefore be non-compensable. A model that invents Subject dialogue, breaks a verbatim-only contract, or emits an artifact without required provenance is not “slightly worse”; it is uncertified for that task. Likewise, a model that attempts an unauthorized tool or model outside its Agent policy must fail rather than receive a partial quality score.

Certification also feeds routing. The router needs more than a list of available models. It needs a matrix of **certified capability, cost, latency, and risk**. A cheap model may become the default for deterministic classification or low-risk ranking. A stronger model may be required for global transcript synthesis or complex collision analysis. An expensive control model can serve as an escalation target when the first pass fails validation. This turns benchmarking into an operational decision system rather than a report published once per quarter.

Human review is part of the benchmark, not a separate qualitative exercise. Operator acceptance, repair rate, rejection disposition, and time-to-correction reveal capabilities that offline benchmarks can miss. A model may score well on a gold dataset but still create production friction because its candidates require constant explanation or repair. CAE therefore needs production-facing evaluation metrics such as accepted-candidate rate, human correction rate, evidence-rejection rate, and artifact rework rate.

The certification loop is consequently:

**Candidate model → CAE task suite → semantic and governance evaluation → economic measurement → human review → certification decision → routing policy → production telemetry → re-evaluation.**

The model never becomes the authority simply because it passes. Certification says, “this intelligence is sufficiently reliable for this declared transformation under these conditions.” It does not say, “this model may override the system.” Contracts still retain authority. The same model can be certified for one task and rejected for another without contradiction.

The strategic value of this system is compounding. Every governed production cycle creates new failure examples, corrections, successful cases, and cost observations. Those can improve the benchmark itself, which improves certification, which improves routing, which reduces wasted inference, which reduces Operator correction, and which eventually supports CAE-specific post-training. The benchmark becomes a memory of what “good” means inside the actual product.

CAE should therefore treat evaluation as infrastructure, not marketing. A model leaderboard can tell the world that a model is impressive. CSEB and the certification system tell CAE whether that model can be trusted with a particular piece of the human-evidence pipeline. That is the standard the Product Brief should defend: **certify intelligence against CAE's real transformations, enforce hard constitutional failures separately from soft optimization trade-offs, and let measured evidence determine routing and evolution.**
