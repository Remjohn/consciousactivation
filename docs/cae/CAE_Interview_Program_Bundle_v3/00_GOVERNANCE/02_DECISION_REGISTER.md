# Interview Program Decision Register

## D-001 — Existing Interview Composer remains the boundary
**Decision:** Extend the current Composer; do not create a second Interview Harness.
**Reason:** Existing repository ownership already covers Guest Research Package, Activative Interview Brief, and Composer Session.
**Source:** repository verification + supplied conversation.
**Disposition:** adopted.

## D-002 — Hypothesis is strategic unit, but not a new canonical object by default
**Decision:** The system reasons over candidate hypothesis instances using the existing activation-hypothesis / portfolio authority where possible. Any adapter is derived and must preserve upstream identity.
**Reason:** The conversation identified hypothesis as the right strategy unit, while the brownfield rule prohibits redundant ontology.
**Disposition:** adopted provisionally.

## D-003 — 96 is candidate search volume, not a hard quota
**Decision:** ~96 is a planning target for candidate generation/search; selection must optimize useful diversity, not raw rank alone.
**Disposition:** adopted.

## D-004 — 16–24 are semantic acquisition targets
**Decision:** The selected portfolio is a set of high-value hypothesis lines that the Interview Program is expected to test/acquire against the Guest, not 16–24 guaranteed final content pieces.
**Disposition:** adopted.

## D-005 — ~32 content pieces is an aspiration, not a quota
**Decision:** Downstream output is elastic. One hypothesis may yield multiple viable content candidates; another may yield none. No force-fit is permitted.
**Disposition:** adopted.

## D-006 — Question is a semantic bridge
**Decision:** Question generation occurs after hypothesis geometry and content/archetype intent are known. Question mechanisms must declare expected evidence/response shape and downstream compatibility.
**Disposition:** adopted provisionally.

## D-007 — Bounded adaptive planning
**Decision:** Maintain a deterministic coverage spine plus a bounded 3–5 candidate next-question frontier at runtime.
**Disposition:** adopted.

## D-008 — Evidence and inference remain distinct
**Decision:** Guest-stated evidence, system inference, and Guest-validated interpretation must remain distinguishable in runtime lineage.
**Disposition:** adopted.

## D-009 — Operator is authorization boundary
**Decision:** Machine-generated or regenerated candidates cannot launch a Brief without explicit Operator approval through an authoritative persistence path.
**Disposition:** adopted.

## D-010 — No primitive canonization from the bundle alone
**Decision:** Audit-derived mechanisms remain synthesis candidates until a separate promotion decision establishes their canonical status.
**Disposition:** adopted.

## D-011 — 12 dimensions are coordinates, not themes
**Decision:** The candidate 12-dimension basis is a provisional coordinate model to be reconciled against existing CAE objects, SDA/SFL, audit evidence, and runtime structures before canonization.
**Disposition:** adopted provisionally.

## D-012 — Format/archetype participates upstream
**Decision:** Format/archetype/coalition intent constrains desired response structures and therefore participates in question design; it is not a downstream decoration.
**Disposition:** adopted.
