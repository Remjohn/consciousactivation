# Reality-Contact & Reward-Hacking Protocol

## Evidence ladder

### E0 Structural
Schemas parse; required fields exist; forbidden duplicate canonical objects are absent.

### E1 Repository
Real imports, real owner modules, real repository/persistence paths, real error behavior.

### E2 Controlled integration
Disposable/controlled infrastructure demonstrates the cross-module behavior.

### E3 Runtime reality
Production-equivalent staging demonstrates the complete Interview Program flow.

### E4 Human/content reality
Operator inspects whether acquired material is actually specific, grounded, useful, and compatible.

## Mandatory false proofs

1. receipt without real evidence;
2. valid question referencing nonexistent hypothesis;
3. valid reference from wrong workspace/session;
4. generic answer passing structural tests;
5. story/archetype label without narrative evidence;
6. high heuristic score accepted as authenticity proof;
7. quantity quota met with low-value questions;
8. machine auto-approval without Operator authorization;
9. stale client overwriting new decision;
10. UI lock not enforced server-side;
11. rejected candidate present in launch payload;
12. fake/mock AIR reference making the UI appear integrated.

## Human test

At least one accepted and one rejected candidate must be reviewed by the Operator. The report must explain the semantic difference, not merely the score difference.
