# step-02-module-boundaries.md

## Purpose

Derive module boundaries from the reconstructed product rather than from arbitrary subsystem naming.

## Rules

1. Read this step completely before acting.
2. Do not load future steps.
3. Inspect evidence before making claims.
4. Preserve claim status.
5. Update the workflow artifact/state required by this step.
6. Stop at a human decision boundary.
7. Do not substitute a downstream artifact for missing upstream evidence.

## Output

Update the current CAE-BMAD workspace according to the parent SKILL.md artifact contract.

## Failure

If required evidence is unavailable:

- record the missing evidence,
- do not fabricate it,
- classify the affected claim as MISSING or PROPOSED,
- route to the smallest useful recovery action.
