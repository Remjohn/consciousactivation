# CAE Operator Gate Checklist

Use this after each mandate. Do not review only whether files exist. Review whether the claimed architectural property was actually established.

## 1. Scope
- [ ] The agent touched only authorized files and systems.
- [ ] Adjacent problems were recorded rather than opportunistically fixed.
- [ ] The output matches the mandate objective.

## 2. Authority
- [ ] Definition authority is explicit.
- [ ] Runtime authority is explicit.
- [ ] Change/promotion authority is explicit.
- [ ] No source/projection mismatch was silently ignored.

## 3. Evidence
- [ ] Every major claim has an evidence class.
- [ ] Runtime claims were tested against the real environment where relevant.
- [ ] A test result is not being treated as wider proof than it supports.

## 4. Taste / reward-hacking
- [ ] At least one false-proof case was attempted.
- [ ] The test could not pass by satisfying only superficial structure.
- [ ] For editorial work, I inspected at least one positive and one hard-negative example.
- [ ] Score inflation, duplicate-source inflation, and generic-output paths were considered where relevant.

## 5. Lineage
- [ ] IDs and versions remain traceable.
- [ ] Evidence can be traced back to source/media.
- [ ] Derived artifacts can be recomputed or their derivation is recorded.

## 6. State / isolation
- [ ] Workspace/Guest scope is preserved where applicable.
- [ ] Historical state was not destructively overwritten.
- [ ] Receipts/events exist for authoritative state changes.

## 7. Stop discipline
- [ ] The agent asked the exact gate question.
- [ ] The next mandate has not started early.
