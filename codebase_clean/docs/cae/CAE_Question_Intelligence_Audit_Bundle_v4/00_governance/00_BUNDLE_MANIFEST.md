## Absolute rules

1. **No canonical Question Primitive may be created, imported, or integrated before every assigned book has a completed and operator-accepted audit.**
2. Existing `PRM-QST-*` candidates from earlier work are quarantined hypotheses only. They are not evidence and must not bias the audits.
3. Each book receives its own execution mandate, its own source verification, and its own `AUDIT_<title>.md` artifact.
4. The audit must read the actual source text available in the local environment. Summaries, reviews, snippets, or model memory cannot substitute for the required reading.
5. If the full source cannot be accessed, the mandate fails and the agent must stop with `SOURCE_ACCESS_FAILURE`.
6. Existing taxonomy and orthogonal dimensions are hypotheses. They may be retained, refined, split, merged, renamed, or expanded when the book evidence warrants it.
7. The audit is allowed to produce **zero** canonical candidates. No mechanism is promoted to satisfy a quota.
8. A passing automated check is not sufficient evidence of taste, usefulness, or mechanism validity. The audit must preserve explicit source evidence and failure boundaries.
9. The Operator reviews each completed audit before the next book is treated as authoritative research material.
10. Only the later Primitive Creation Skill may create canonical primitive YAMLs.

## Audit output rule

Every book audit is a research artifact, not a production registry. It must clearly distinguish:

- source-derived claims
- auditor interpretation
- CAE application hypotheses
- proposed taxonomy changes
- mechanisms worthy of later primitive evaluation

## Required audit length

Target **3,600–3,800 words** per book. This is a density target, not permission to pad. The source must drive the content.
