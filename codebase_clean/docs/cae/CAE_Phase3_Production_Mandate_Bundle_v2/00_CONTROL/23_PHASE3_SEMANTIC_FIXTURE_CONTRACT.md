# Phase 3 Semantic Fixture Contract

Every semantic Program must be verifiable against a bounded corpus.

Positive fixture classes:
- real/approved Workspace
- Guest source evidence + historical memory
- protected Guest DNA representation
- Audience Cognitive Islands/current state
- multiple research sources
- duplicate concept expressions
- ambiguous entity aliases
- related concepts
- contradictory claims
- ResearchSignal
- CollisionHypothesis
- InterviewBrief
- InterviewResponse
- EvidenceSegment
- SemanticAnnotation
- ContentCandidate

Negative/contrastive fixtures:
- false concept merge
- false entity merge
- source/version mismatch
- stale knowledge projection
- unsupported Guest claim
- Audience state mismatch
- mutated protected evidence
- synthetic candidate masquerading as real
- missing lineage/receipt
- wrong Workspace
- invalid state transition

Fixture IDs must be stable and resettable.
