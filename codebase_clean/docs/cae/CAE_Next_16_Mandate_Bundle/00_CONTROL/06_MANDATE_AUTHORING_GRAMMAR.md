# Mandate Authoring Grammar — M49–M64

This wave deliberately preserves the established CAE mandate grammar used by the M01–M48 bundle. The prior bundle's validation contract requires every mandate to contain objective, mandatory reading, scope, prohibitions, verification, completion/stop, rollback/recovery, and operator decision; every activation prompt names authority, scope, proof and STOP.

## Mandatory structure

1. Decision / Objective
2. Governing doctrine and authority
3. Mandatory reading before action
4. Exact scope
5. Required implementation behavior
6. Verification and evidence
7. Completion / stop condition
8. Rollback / recovery
9. Operator decision
10. False-proof / reward-hacking defense
11. Out-of-scope but recorded

## CAE execution grammar

`MANDATE → PRD/FR reconciliation → OBJECT/CONTRACT reconciliation → implementation → deterministic validation → reality-contact test → evidence → receipt → CURRENT.md synchronization → operator gate`

The prior CAE doctrine explicitly distinguishes `DOCUMENTED` from `CODE_EXISTS`, `TEST_VERIFIED`, `RUNTIME_VERIFIED`, and `OPERATOR_ACCEPTED`. This distinction is preserved here.

## Brownfield rules

- Read the current repository before acting.
- Search exact symbols/callers before editing.
- Reuse existing authorities rather than create replacements.
- Treat external repositories as patterns, never as CAE authority.
- Never promote a capability because a file exists.
- Every important verifier gets a false-proof test.
- Phase-close mandates update the relevant current-state records and STOP.
