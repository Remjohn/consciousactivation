# CAE Current-State Reconciliation & PRD Synchronization Mandate Bundle

Version: `1.0.0`
Status: `GOVERNED EXECUTION BUNDLE — OPERATOR AUTHORIZATION REQUIRED`
Prepared: `2026-08-30`

## Purpose

This bundle authorizes a bounded brownfield operation whose sole purpose is to establish one verified current state of the Conscious Activations repository and synchronize the canonical PRD to that verified state before any new runtime-convergence build program begins.

This is a **truth-establishment program**, not a feature-development program.

## Governing execution skills

Gemini MUST load and obey the repository's current authoritative execution material before acting:

1. `docs/cae/cae_mandate_bundle/01_CA_MANDATE_AUTHORING_PROTOCOL.md`
2. `docs/cae/cae_mandate_bundle/02_CA_GEMINI_MANDATE_EXECUTION_SKILL.md`
3. `docs/cae/skills/EVIDENCE_TO_AIR_FIRST_SLICE_SKILL.md` when evidence/receipt/state claims touch the first-slice evidence boundary.
4. The repository's current PRD, Tech Specs, control-state records, object constitutions, skills, and existing mandate records named by the selected mandate.

The mandate-authoring protocol requires explicit authority separation, exact scope, evidence classes, state transitions, verification standards, stop conditions, operator decisions, and bounded activation prompts. The Gemini skill requires: `LOAD AUTHORITY → VERIFY PRECONDITIONS → BUILD PLAN → EXECUTE WITHIN FILE BOUNDARY → VERIFY → RECORD EVIDENCE → UPDATE CONTROL STATE → COMMIT → REQUEST OPERATOR DECISION → STOP`.

## What this bundle does NOT authorize

- No runtime-convergence implementation.
- No new semantic ontology.
- No new canonical object family.
- No speculative migration to MCP, Supabase, or other transport/storage technology.
- No removal of files merely because they appear redundant.
- No silent merging or renaming of authorities.
- No weakening of tests to obtain a green result.
- No claim that a mandate was executed unless its repository evidence exists.

## Program sequence

`CA-CSR-01 → CA-CSR-02 → CA-CSR-03 → CA-CSR-04`

CA-CSR-01 and CA-CSR-02 are sequential because the second depends on the evidence captured by the first. CA-CSR-03 is the only mandate authorized to update `docs/PRD/CURRENT.md`. CA-CSR-04 independently verifies the resulting state and closes the reconciliation operation.

## Expected result

At completion there must be one operator-verifiable answer to:

> **What does the repository actually contain, which artifacts are authoritative, which capabilities are truly implemented/proven, which are merely specified or claimed, what remains open/quarantined, and does `docs/PRD/CURRENT.md` now accurately say so?**

A “complete” result without repository evidence is a failure.
