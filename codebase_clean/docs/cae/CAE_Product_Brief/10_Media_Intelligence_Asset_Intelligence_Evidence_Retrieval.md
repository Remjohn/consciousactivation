# 10. Media Intelligence, Asset Intelligence & Evidence Retrieval

CAE's evidence system must extend beyond text. Activation often depends on the relationship between what the Subject says and the media that surrounds the statement: an archival clip, a cultural reference, a reaction, a real-world example, a previous interview moment, a still image, or a short pattern-interrupt insert. The product therefore needs a governed media-intelligence layer that can discover, resolve, annotate, verify, and promote usable media without collapsing “search result” into “approved asset.”

The correct product abstraction is **Evidence Retrieval**, not “PlayPhrase integration.” A deterministic phrase-to-clip tool is useful because it demonstrates one important primitive: given a textual expression, locate its exact occurrence in a source, resolve the timestamp, and extract the underlying media fragment. But CAE needs a broader capability that can operate across source classes and editorial roles.

The canonical EvidenceLocator flow is:

**semantic or lexical need → candidate evidence → source resolution → exact span or timestamp → context expansion → provenance and rights verification → human resolution where required → governed asset → composition.**

This makes retrieval part of the production chain rather than a convenience feature living beside it. The Operator should be able to ask for a specific phrase, concept, emotion, example, contradiction, or editorial role. CAE can then use the cheapest suitable retrieval method, but every discovered result must resolve back to authoritative source evidence before it can become production material.

The repository already provides a strong foundation. The asset-intelligence domain defines source types including `REAL_WORLD`, `PREVIOUS_INTERVIEW`, `ARCHIVAL`, `MOVIE`, `SOCIAL_MEDIA`, and `CULTURAL`. It also distinguishes media types such as `VIDEO_CLIP`, `AUDIO_BITE`, `STILL_IMAGE`, and `MOTION_GRAPHIC`, and editorial insert roles including `SEMANTIC_SIMILE`, `PATTERN_MATCH`, `PATTERN_INTERRUPT`, `COMEDIC_PUNCTUATION`, `FORESHADOWING`, `CONTRAST`, `CULTURAL_RECOGNITION`, `EMOTIONAL_AMPLIFICATION`, and `WORLD_BUILDING`. The domain object also records timestamps, semantic role, source SHA-256, and rights metadata. This is a product-level asset model, not simply a file browser. citeturn672518view0

Asset governance is equally concrete. The asset annotator rejects generic captions, enforces a preferred 3–6 second insert duration with a 2–8 second tolerance, and requires a license identifier or proof URL when an asset is marked cleared. These checks illustrate how CAE should treat media: an asset must have semantic purpose, source identity, temporal precision, and an explicit rights state before it becomes safe to reuse. citeturn672518view1

The retrieval system provides another critical architectural principle: **authority before ranking**. The current Pipeline `AuthorityFirstRetrievalService` first filters candidates by authority state and lifecycle state, as well as category, format, role, source kind, tags, permitted actions, and interview provenance. Dense ranking is explicitly advisory and is applied only after the eligible candidate set has been determined. This is exactly the right foundation for semantic media retrieval. A model may rank eligible options; it must not make an ineligible source eligible simply because it looks relevant. citeturn672518view2

CAE should therefore support a retrieval hierarchy. Layer one is deterministic retrieval: exact phrase search, regex, transcript lookup, timestamp lookup, and known-source resolution. Layer two is semantic retrieval: concepts, themes, emotional states, editorial roles, and meaning-based similarity. Layer three is source resolution: map a candidate to an exact transcript segment, file, time range, or object. Layer four is governance: verify provenance, rights, authority, lifecycle, and permitted use. Layer five is asset promotion: turn the validated result into an approved production object available to composition.

This layered model preserves both precision and economics. Exact lexical searches should not consume frontier inference. Semantic search should be invoked when the meaning of the request cannot be represented adequately through deterministic methods. Multimodal reasoning may be reserved for cases that genuinely require visual or audio interpretation. Routing can decide which retrieval strategy to use, but the final asset still passes through the same governance boundary.

Context expansion is particularly important. A retrieved phrase may be correct but misleading when detached from the surrounding statement. EvidenceLocator should therefore support expansion around an exact hit: prior sentences, subsequent qualification, speaker identity, scene context, and related evidence references. The goal is not to return the shortest possible clip. It is to return the smallest context that preserves meaning while respecting the intended editorial role.

Contradictions and failed alternatives should also remain visible where appropriate. A media candidate that was rejected because its rights state was unresolved, its context conflicted with the requested meaning, or its insert role did not fit the composition contract can still provide useful learning signal. The Pipeline projection model already includes relationship edges, contradiction references, supersession references, failed-alternative flags, evidence quality, and permitted actions. That suggests a future in which media candidates participate in the same governed knowledge ecology as textual evidence rather than remaining isolated file records. citeturn672518view2

Human resolution remains important. The Operator should not have to understand search internals, but they should be able to see why a candidate surfaced and what would happen if it were promoted. A useful preview should expose source, timestamp, contextual transcript, semantic role, rights state, and any relevant confidence or match basis. The Operator can then accept the asset, reject it, request alternatives, or provide a correction. That correction becomes part of the evidence trail.

The multi-surface application strategy reinforces this. The primary App can provide full media exploration and evidence inspection. Slack or Telegram can communicate that a candidate is ready for review or accept a simple decision. A Telegram Mini App can provide the richer visual preview needed when seeing the actual clip matters. But every surface is still an adapter over the same EvidenceLocator and runtime. No channel becomes the authoritative asset catalog.

Media intelligence must also respect the authenticity boundary. A retrieved clip is not automatically licensed for reuse. A cultural reference is not automatically factually or contextually appropriate. A previous interview is not automatically current. A synthetic visual is not automatically evidence of a real-world event. The asset layer should preserve the distinction between source evidence, editorial use, generated support material, and approved production asset.

This means the product should treat media assets as **evidence-bearing objects with lifecycle**. Discovery creates a candidate. Annotation gives the candidate semantic and temporal structure. Verification establishes rights and provenance. Human or governed system resolution promotes it. Composition consumes the approved object. Release records its inclusion. Outcome data can later reveal whether a particular media role actually improved activation.

Evidence Retrieval also closes an important loop with the interview system. The same engine that locates a movie or archival clip can retrieve prior Subject expression, exact previous statements, or related evidence moments. This makes “retrieval” a cross-domain capability rather than a media-only feature. The product becomes capable of resolving the evidence needed for a planned activation moment regardless of whether that evidence lives in a current transcript, a prior interview, an archive, or an external media source.

The resulting abstraction is deliberately broader than any one vendor, search engine, or repository:

**EvidenceLocator = search + locate + resolve + contextualize + verify + promote.**

That abstraction gives CAE a durable path to multimodal evidence intelligence while retaining the constitutional rule that relevance alone is never enough. A candidate becomes production material only when the system can prove where it came from, why it is relevant, that it is eligible, and what authority permits its use.

Media intelligence is therefore not decoration added to a text engine. It is a natural extension of CAE's evidence sovereignty principle. The engine is designed to activate human meaning; once activation depends on text, image, audio, video, and cultural reference together, those forms of evidence must be governed by the same causal discipline.
