## 2. Evidence Classification Definitions

- **`DIRECT_OBSERVATION`**: Directly inspected static repository files, directory trees, migrations, or application code.
- **`STATIC_VERIFIED`**: Re-executed automated static validator (AST/YAML/specification structure) with clean exit code 0.
- **`STAGING_PROVEN_E3`**: Executed against isolated, disposable Supabase/PostgreSQL 17.6 + private Storage staging environment with checksum verification, forced transaction rollback, and confirmed object deletion.
- **`E2_REPOSITORY_INTEGRATED_E3_STAGING_PROVEN`**: Multi-tier execution spanning local real service engine (SQLite) and staging PostgreSQL/Storage, with negative tamper tests, zero local mutations, and complete cleanup.
- **`QUALIFIED_BOUNDED`**: Claim accepted strictly within its explicit negative-case and non-claim boundary.

## 3. Explicit Prohibitions and Non-Claims Maintained

1. **No Production Parity or Authority Cutover**: PostgreSQL/Supabase is proven exclusively as a staging foundation. SQLite service authorities remain the active runtime baseline.
2. **No Repository-Wide PostgreSQL Authority**: Neither Pipeline, VAE, AIR, Campaign, Builder, nor Interview Expression services have been rewired to PostgreSQL.
3. **No SFL Family Invention or Silent Resolution**: The 5 quarantined failure assets (`SFL-FAM-005, 006, 007, 009, 012`) remain locked in quarantine until an accountable lineage source resolves them.
4. **No Primitive Collision Normalization**: Duplicate `EXP-TRG-001` records remain quarantined; resolver refuses ambiguous requests.
5. **No Runtime Orchestrator or JIT Integration**: Runbooks and Skills are procedural specifications, not executing orchestrator loops.
6. **No Live API or User Route Bridge**: The `InterviewExpressionSourceBridge` is an internal callable adapter; no HTTP route exposes it.
7. **No E4 Semantic, Taste, or World-Outcome Proof**: Structural and state-transition receipts do not establish perceptual sharpness, human truth, or real-world audience impact.
