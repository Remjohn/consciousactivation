## 1. Governing Rules & Classification Protocols

Every object mapped below conforms to the following non-negotiable rules:

1. **Candidate Classification:** All assigned primary classes are candidate designations only; no primary class is ratified until its respective `CA-CANONICAL` phase constitution is approved.
2. **Three Distinct Authority Axes:**
   - **Canonical Definition Source:** The reviewed source artifact, version, lineage, and semantic authority.
   - **Target Runtime Representation:** The verified PostgreSQL relational projection used by typed operations.
   - **Change and Promotion Authority:** The governed role/process authorized to alter or promote either axis.
3. **Tenancy Boundary:** `Workspace` is the sole candidate tenant boundary. `Guest` is a workspace-local entity and is never a tenancy key or global identity.
4. **Evidence Labeling:** Every assertion is classified by evidence type: `[EXECUTABLE]`, `[SCHEMA]`, `[MIGRATION]`, `[REGISTRY_SOURCE]`, `[DOCUMENT]`, `[TEST]`, `[HYPOTHESIS]`, or `[OPERATOR_DECISION_REQUIRED]`.
5. **No Implicit Identity Merges:** Cross-workspace record merging is strictly prohibited; exceptional links require explicit, auditable mapping objects.
