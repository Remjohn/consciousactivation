# Operator Gate Sequence — v3

## Gate 0 — PRD / authority ratification

Approve only when:

- the proposed PRD delta is mapped to actual current FR/story authorities;
- no missing story text has been invented;
- PRD maintenance obligations are understood;
- build authority is explicitly granted or withheld.

## Gate 1 — Brownfield truth

Approve only when M01 identifies actual current owner, symbols, routes, schemas, persistence, and tests.

## Gate 2 — Hypothesis integrity

Approve only when:

- 96 is treated as candidate search volume;
- selected 16–24 is a working semantic-acquisition portfolio;
- useful diversity is measured;
- existing AIR ownership is preserved.

## Gate 3 — Question synthesis

Approve only when:

- audit-derived mechanisms are source-traceable;
- merge clusters are explicit;
- promoted candidates have a boundary;
- no unaudited primitive is silently canonized.

## Gate 4 — Brief compilation

Approve only when the existing Activative Interview Brief is the actual compiled output and current Composer validation passes.

## Gate 5 — Operator Studio

Approve only when real candidate retrieval, persistence, feedback, lock, selection, regeneration, concurrency, and authorization are demonstrated.

## Gate 6 — Runtime adaptation

Approve only when the deterministic spine and bounded frontier both exist and answer observations demonstrably alter the next move.

## Gate 7 — Evidence

Approve only when Guest evidence, inference, and validation are distinct and traceable.

## Gate 8 — Composition compatibility

Approve only when question acquisition exposes downstream format/archetype intent without forcing unsupported evidence.

## Gate 9 — Content menu

Approve only when candidates are traceable to authenticated evidence and Operator selection remains authoritative.

## Gate 10 — Reality contact

Approve only when staging proves the real chain and adversarial false proofs fail.

## Gate 11 — Documentation closure

Approve only when PRD/spec/gap surfaces are updated in-session and all remaining claims are explicitly classified.

## Operator questions

1. Did we extend the existing Interview Composer rather than create another engine?
2. Did any adapter accidentally become canonical?
3. Can every selected hypothesis be traced back to upstream evidence and forward to a required acquisition target?
4. Can every question be traced to a hypothesis/objective/mechanism/evidence requirement?
5. Can a fake receipt make the system claim success?
6. Can a high score bypass semantic/human review?
7. Can a stale client overwrite an Operator decision?
8. Can format/archetype labels manufacture an unsupported content claim?
9. Is every “verified” statement actually backed by a current execution artifact?
